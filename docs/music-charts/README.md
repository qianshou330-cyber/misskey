## 数据流与边界

- 前端可见且页面激活时每 60 秒读取本站接口；首页消费者共享请求。页面隐藏、退出或切换历史榜单时取消相应请求。加载失败不阻塞原时间线。
- 后台使用独立 BullMQ 队列 `musicCharts`，不占用原系统任务队列。只有环境变量 `PUBO_MUSIC_CHARTS_ENABLED=true` 才启用采集；默认关闭。
- 每个已启用来源使用固定 UTC 分钟的小时调度，任务串行执行。启动或重启不会立即采集，也不补跑启动前的旧时段；已有退避和冷却时间优先。每小时检查不保证来源每小时产生新结果。
- 复用 `HttpRequestService`，仅允许登记的 HTTPS 来源，拒绝重定向，单次请求限时 10 秒、正文上限 1 MiB。首先检查通用客户端访问规则，不冒充搜索机器人、不绕过限制、不购买付费服务。
- 来源拒绝、限流或访问规则禁止后至少等待 24 小时；普通失败逐步退避，最长 6 小时。后端网页解析失败、缺页、榜期不一致和 HTTP 200 拦截页均不会生成“未上榜”。
- 官方榜期、最近检查时间 `checkedAt` 与最近成功读取时间 `lastSuccessAt` 分开保存；榜期以 UTC 存储，页面统一显示韩国时间。失败检查不能更新成功时间，缺少成功时间时不以检查时间代填。重复榜期去重，较迟完成的旧请求不能覆盖新状态，旧榜期不能回退最新结果。
- 历史仅从实际验证通过的采集开始；走势图缺口保留为空。“监控以来最佳”只代表本站已有观测，不代表平台全历史最佳。

## 接口与持久化

两个接口均为匿名只读，支持 GET/POST，限流 120 次/分钟，HTTP 缓存与进程内读缓存均为 30 秒。访问接口不会触发上游采集。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `music-charts/summary` | 无 | 五榜官方状态及原有数据；每榜含 `maxRank`（100 或 200），新增可空 `reference`，独立说明第三方来源、范围、结果、名次与各时间 |
| `music-charts/history` | 必填 `chartKey`，仅允许上表五键 | 最近七天的固定小时/日槽位和 `maxRank`；缺失记录明确为 `missing`，最多 169 个点；旧 MV 键返回参数错误 |

公开状态为 `pending / available / restricted / unavailable / stale`；结果为 `unknown / ranked / unranked / out_of_scope`。来源失败时可继续显示上次有效结果，但保留原榜期并标记其状态。公共类型经正常 SDK 生成流程生成，不手工维护副本。

已发布迁移 `packages/backend/migration/1792011832193-MusicCharts.js` 提供两张表，本轮五榜调整不新增或修改迁移：

- `music_chart_state`：每榜一个最新状态，保存退避时间、有效名次、观测最佳及开始时间。
- `music_chart_snapshot`：以榜单键和官方榜期为联合主键，保存经验证的观测；内部保留八天供七天视图边界使用。

状态与快照在同一事务内提交，按榜单使用事务锁。没有修改账号、Chat、私有附件或其他已有业务表。

## 第三方参考

- 仅请求 `https://www.chartradar.app/charts/melon`、`/charts/genie`、`/charts/bugs` 以及访问规则 `/robots.txt`。解析 HTML 内已有 JSON，不执行脚本，不请求内部 API；使用既有透明请求身份，拒绝重定向，不换身份绕过拒绝。
- Melon 页面分别验证日榜与 TOP100 的完整 100 条；Bugs 验证完整 TOP100；Genie 验证完整 TOP250 后只取前 200。标题与歌手规范化匹配 NEON；重复匹配、缺行、异常榜名/国家/时间和结构变更拒绝更新。没有提供 HOT100 的合格参考来源。
- 使用 `PUBO_MUSIC_CHART_REFERENCES` 的逗号分隔白名单逐项启用，允许 `melon-daily,melon-top100,genie-realtime,bugs-realtime`，默认为空。仍要求原采集总开关为 true。专用 musicCharts 队列的 `reference:melon/genie/bugs` 调度改为每小时 UTC 15/17/19 分；没有启用的来源不创建任务。本次不扩大已批准的参考白名单。
- 请求 10 秒、HTML 3 MiB、访问规则 64 KiB；401/403/429 或规则拒绝至少退避 24 小时，普通失败从 15 分钟逐步退避到 6 小时。
- Redis 的 `musicChartReference:v1:` 独立缓存保存读取尝试与快照；参考服务没有数据库依赖，不写两张正式榜单表。快照到期为来源采集时间加七天，重复数据不能续期。失败保留原结果并标注，旧请求不能覆盖新结果。小时数据超过三小时、日榜超过七十二小时为旧参考。
- 摘要只做有界缓存读取，不触发抓取。`reference` 包括 `provider/sourceUrl/scope/status/result/rank/sourceTimeLabel/sourceFetchedAt/checkedAt/lastSuccessAt/basis`，以及可空的 `diagnostic` 和 `nextAttemptAt`；`result` 为 ranked/not_found/unknown。未检出只说明第三方参考榜没有检出，不能宣称官方未上榜。
- 首页显示“参考第 N”或“上次参考第 N”；详情分别展示来源原始时间文本 `sourceTimeLabel`、第三方采集时间 `sourceFetchedAt`、本站最近检查时间 `checkedAt` 与最近成功读取时间 `lastSuccessAt`。这些时间不相互替代，小时标签不会拼成官方榜期。有效官方结果优先；参考数据不参与正式历史、涨跌或最佳纪录。

### 2026-10-16 ChartRadar Melon 受控恢复候选

当前候选基于已发布的 `pubo-a2o-charts:hourly-20261016`（`sha256:0fab146c8f2c04eee045f15591a01f35ced625affa912d5bc2a40b3cac786c2f`）。下面更早的 default-zh / compact 回退说明仅为历史记录，本次回退目标为 hourly，保留小时错峰、默认中文和私聊附件保护。

- 诊断只允许固定的失败阶段、原因码、HTTP 状态、有效 Retry-After 时间和耗时，不保存原始错误、响应正文或请求凭据。规则响应无效与明确禁止分别记录；无法确认规则时不读取榜单正文。旧失败记录没有诊断信息时显示未记录，不推断历史失败原因。
- 有效 Retry-After 只延长暂停；失败及并发晚到的普通成功请求不能提前清除已有失败暂停。尝试记录至少保留至暂停结束后一小时，排名快照仍按来源采集时间加七天到期，不续期旧数据。
- `nextAttemptAt` 表示最早允许再次尝试的时间，不承诺该时刻一定执行。现有每小时固定时隙、成功冷却与退避仍生效。首页及手动刷新只读取本站缓存。

- 任一次采样失败即停止本轮恢复，不切换只有新文案的版本，不缩短原暂停，不更换身份、代理或会话重试。恢复写入如返回不确定结果，先只读核对，不自动重试或假定未提交。
