# PUBO 女团音源榜

此模块取代首页 A2O LITE 五榜摘要；保留原 `music-charts/summary`、`music-charts/history` 接口及其历史数据，不把 ChartRadar 记录改标为官方结果。

## 展示与数据含义

- 新页面 `/music-charts/kpop`，原 `/music-charts/a2o-lite` 在客户端转向新页面。
- 监控 A2O LITE、Hearts2Hearts、KiiiKiii、Baby DONT Cry、ifeye。艺人匹配为平台隔离的 ID 和有限完整名称；不会包含匹配任意带有 A2O 的艺人。
- 首页默认 Melon TOP100，只展示五团合并后排名最前的两首。详情支持平台、Melon 榜种、团体和歌曲筛选。
- Melon 日榜、TOP100、HOT100 D100/D30 各 100 首；Genie 四页同一期共 200 首；Bugs 和 FLO 各 100 首。
- Apple Music 韩国 TOP100 是公开歌单位置；Spotify 是韩国 TOP50 的公开 30/50 预览；腾讯音乐是由你榜韩语榜前十预览，不是 QQ 音乐 toplist/4。预览未覆盖不表示未上榜。
- 官方榜期、本站读取时间及内容首次观察时间分别保存。未知来源更新时间明确显示未知；重复读取相同数据不产生新榜期或刷新首次内容观察时间。
- 七天走势和最佳位置仅比较同榜种、覆盖范围、位置含义和时间依据。官方期次与本站观察记录不混用；缺口不补造排名。

## 运行与访问边界

没有新增独立服务器、用户体系、依赖或认证方式。解析器已移入 Misskey 后端，请求通过现有 HttpRequestService；新增专用 BullMQ 队列和 TypeORM 表。

`PUBO_KPOP_CHARTS_ENABLED=true` 启用模块并停用旧榜单的对应调度；`PUBO_KPOP_CHARTS_KEYS` 是通过生产验证的榜种键，逗号分隔，默认空。未通过验证的平台保留页面入口，不展示假造排名。生产启用键必须由实际验证结果决定，不能依据包内样例或单元测试。

每项使用固定小时槽、持久化已尝试标识和 PostgreSQL 来源锁。启动和页面刷新不立即采集；微小执行延迟可继续原槽，过期槽不补跑。读取 API 仅访问本站数据。前端每 60 秒检查本站缓存，隐藏后暂停。

只允许登记的公开来源地址，记录 robots 访问规则；请求不带登录 Cookie，不使用代理或更换身份。请求上限 10 秒、页面 3 MiB，robots 64 KiB；按声明间隔执行并释放响应连接。任何分页不完整、重复行、榜期冲突、身份冲突或拦截页均拒绝整次更新，不保存原始页面。

临时失败退避 1/2/4/8/24 小时，登录或验证码挑战至少 24 小时；有效 Retry-After 只延长暂停。到期后的正常小时槽允许恢复；人工停用不会自动解除。失败保留最后有效快照并显示固定原因。未知榜期仅根据最近成功读取判断采集健康，不推断平台已更新。

## 公开只读接口

- `music-charts/kpop-summary`：可选 `chartKey`，默认 Melon TOP100；十榜元数据、五团目录及最多两首摘要。
- `music-charts/kpop-chart`：固定枚举 `chartKey`，可选 `groupId`、长度不超过 200 的 `query`、分页 `offset`/`limit`；单页最多 100 条，底层单榜最多 200 条，默认只展示五团歌曲。
- `music-charts/kpop-history`：固定枚举 `chartKey` 和平台内 `songId`；最多七天，响应明确 `official_period` 或 `observation`。

接口不接受外部 URL。公开诊断仅使用固定代码和时间，不返回上游正文、内部异常、Cookie 或令牌。SDK 从后端契约生成。

## 数据与升级

增量迁移 `1792248949504-KpopMusicCharts.js` 新增 `kpop_chart_state`、`kpop_chart_snapshot`、`kpop_chart_entry`；已有业务表和发布迁移保持不变。`down` 只删除这三张新表，是破坏性开发回滚，生产回退不执行它。

快照和状态在同一事务提交；同一期去重、旧响应不能覆盖新数据。规范化数据与哈希保存八天，并保留每榜最后一个有效快照。物理清理由该榜后续有效采集触发；持续停用的榜不写入新数据。

生产发布必须先完成：独立 PostgreSQL/Redis 的迁移 `up → down → up`、实体一致性、多连接锁及队列测试；候选镜像完整空库迁移与真实匿名 API 测试；前端检查和浏览器布局；每个启用榜两次生产实际读取，间隔至少一小时，明确小时榜须观察榜期推进。样例不能导入生产。

发布继承当前带 Chat 私有附件保护的安全镜像。一次性迁移进程显式加载生产配置，核对只存在预期新增迁移，并设置锁等待和执行超时。初始化仅使用经过复核的真实规范化公开数据，不能读写私聊。应用切换只调整 Web 镜像和本模块两项环境变量。

回退前停止新 worker，并仅移除本模块的十个 scheduler；保留新增数据和所有其他队列。恢复原安全镜像及原配置，旧采集仍按原有暂停和小时规则运行。不得回退到私聊附件权限切换前的后端，不修改数据库/Redis 服务配置。
